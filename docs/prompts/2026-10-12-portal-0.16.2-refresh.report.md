**File-backed or live.** Every layer a dependent pushes is a path mount of a folder on disk. Portal still holds the mount in memory, as a `ui:mount:<layer>` node that only an approved snap writes out (design.md 14, 20, 33). So until a snap follows it, a pushed layer is live and is gone after any restart. Once a snap holds it, every boot remounts the folder's newest file.

### Conflicts, and how each was resolved

1. **Portal.Emitters `Mount` restarts Portal twice.** Resolved by order: it runs before Portal.Agent's `Up`, so it has no live layer to wipe. Its own snap saves its six mounts, and step 6 saves the agent's four. A rewrite was rejected: running `Emit` and doing the mount, snap and verify in Portal would copy Portal.Emitters' code. Rules R3 and R4 enforce the order.
2. **Agent `Down` needs a running portal** (it re-posts the environment layer as stopped). Resolved by order: it comes before Portal's Down (R2).
3. **The Agent lane's `Down` throws with no Docker engine.** Resolved by a skip with one line. `Up`'s Preflight starts Docker Desktop itself.
4. **Every restart re-mints the dev token.** Agent `Up` and Emitters `Mount` recover their own tokens. Refresh fetches the current one from `GET .../dev-token` for its snap, and never prints it. Agent `Down` only warns on a stale token (prompt A).
5. **Portal's `Feeds` replaces the portal.** Resolved by leaving it out. The Catalogue reads pushes from the ledger. Run Feeds before Refresh when the stock feeds are wanted.
6. **Portal `Down` before `Dev` is redundant.** Kept, because the brief names it. It costs one stop.
7. **Graph.Node pins disagree over one checkout.** Portal is at v0.4.2 (lifted), Emitters at v0.4.1, the four card repos at v0.3.0, and Agent wants 0.3.2+. The checkout is at v0.4.2. Refresh runs no card-repo tests, so this cannot break a Refresh, and its second line prints the checkout's version. Reported (prompt C).
8. **Emitters' live cards name stale layers.** The mount.yaml files say `environment` and `ledger`, but Agent mounts `agent-environment`, `agent-ledger` and `agent-alerts`. Only labels are affected. Reported (prompt B).

## Choices made without asking (docs/design.md 56)

- The order is in two files: the doc for the reasoning, the psd1 for the data. Pester ties them together.
- Emitters' `Mount` is called unchanged, ordered before the live push, rather than reimplemented.
- Steps run in a child pwsh with file redirection, waiting on the child alone. A portal started by a step inherits its handles, so a pipe would never close.
- The approval uses the dev token from `GET .../dev-token`.
- Agent `Down` is skipped with no Docker engine.
- `Feeds` is not a step.
- `last.json` is written only on a pass, so a regression keeps failing until it is fixed. A failing roll call goes to `failed.json`.
- `-DryRun` is a new build parameter.
- There is no exported function. The Pester block has the tag `Refresh`.
- The manual check list gains item 0.4 (the dry run). The real Refresh is not an item, because its output has not been seen.
