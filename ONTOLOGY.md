> This file defines the terms and the portal's Kinds. [README.md](README.md) says how to build and use it.

# Portal ontology

Module `Portal`, version 0.10.0, id prefix `ui:` (registered to Portal in Graph.Node's id registry since v0.2.3, lifted here; Run and Decision keep the `agent:` ids Graph.Emitter.Agent gave them, and an agent LedgerEntry the `ledger:<seq>` id its layer gave it; Portal never mints either), declared in `ontology.yaml` and validated with `graphnode validate-ontology`. Node, Edge, Envelope, Kind, Layer and Category mean what Graph.Node says (its ONTOLOGY.md); this file adds only the portal's terms.

## Terminology

| Term | Meaning |
|---|---|
| Tenant | Who the portal is run for. One process serves one, `PORTAL_TENANT` (default `default`); every API path names it, `/api/tenants/<tenant>/...`, and any other tenant is 404. Its files are under `tenants/<tenant>/` (docs/design.md 36). |
| Base config | `portal.base.yaml`: the product's defaults (product name, help link, menu), embedded in the binary and never edited by a tenant. |
| Overlay | `tenants/<tenant>/portal.yaml`: what a tenant changes, deep-merged over the base (mappings key by key, lists of items with an `id` item by item, anything else replaced). Base and overlay both pass `schema/portal.schema.json` at boot, and the merge must name the product and give every menu entry a label and a path, or the binary stops. |
| Tenant mode | The overlay's `mode`: `dev`, `demo` or `prod`, prod when absent (`schema/portal.schema.json`); what the tenant is run for, served on `GET /api/tenants/<tenant>` and in the merged config. The banner shows it; dev adds an amber DEV MODE bar, demo a thin blue DEMO bar, neither dismissable. Separate from `PORTAL_MODE`, which hides the Designer (docs/design.md 39). |
| Shell theme | The config's `theme` block, the shell's own settings: not a node and not node display, which stays in State and Theme nodes. `graph.wheelZoomSpeed` (number, 0.1 to 5, base 1.0) scales the Canvas's mouse-wheel zoom step; an overlay may override it, and a value outside the range stops the binary at boot (docs/design.md 37). |
| Menu | The shell's left rail, built from the merged config's `menu` tree and served by `GET /api/tenants/<tenant>/menu` as an envelope of Service and Page nodes. Not the screen graph: it is never written or snapped. |
| Service | Kind. One rail entry (`ui:rail:<service>`): `path`, `order`, `dock` (`bottom` pins it to the foot of the rail: Settings). Its pages hang off it by `has-page`; its icon is its State's `icon`. |
| Page | Kind. One page of a Service (`ui:rail:<service>:<page>`), routed at `/<tenant>/<path>`. `view` says what draws it: `table` (the nodes of `nodeKind`), `screen` (the screen node `screen` names, a Designer's `sections` only when given), `connections`, `users` (the tenant's principals of type user), `agents` (its agents and their runs, at `/<tenant>/agents`), `tokens` (its bearer tokens), `feeds` (its feeds and their cards, read-only), `layers` (the mounted layers), `emitters` (its emitters and the layers they produced, at `/<tenant>/emitters`) or `ledger` (its ledger chains, at `/<tenant>/ledger`). `filter` lists `properties.kind` values offered as chips. A Page's own Pages are the tabs of its item page, `/<tenant>/<path>/<id>`. |
| Principal | Kind. Who may hold a token in a tenant: `ui:principal:<name>` with `type` (`user` or `agent`; only users are created in 0.5.0, agents are minted via Marker, later), `role`, `created` (absent only on dev-bootstrap in `GET .../agents` when `principals.yaml` lacks it) and `createdBy`, the creator's id, absent only on the tenant's first admin. Kept in `tenants/<tenant>/principals.yaml` (gitignored), served by `GET /api/tenants/<tenant>/principals`, added by an admin through `POST` there (Identity/Users' Add). Never on the screen graph. Also who a request is (`GET .../auth/whoami`): a token's principal, or `anonymous` with no token, which reads only (docs/design.md 38). |
| Agent | A principal holding runs, not a Kind of its own: each principal of type `agent`, and each principal whose token mounted a layer of Graph.Emitter.Agent runs. Runs mounted with no principal's token (a legacy token, a `-mount` flag at start) are dev-bootstrap's. Served by `GET /api/tenants/<tenant>/agents`; listed at `/<tenant>/agents` (Identity/Agents), each at `/<tenant>/agents/<name>` (docs/design.md 43). |
| Run | Kind. One agent run: a Run node of a mounted layer whose module is Graph.Emitter.Agent, served under that node's own id `agent:run/<stamp>` with its `layer`, `startedAt`, `stopped`, `finishedAt`, `exit`, `steps`, its decisions counted by effect (`allow`, `deny`, `witness`) and, while a ledger layer is mounted, `ledger`, its count of ledger entries (docs/design.md 45). Joined from its agent by `has-run`. A Run id in two layers is served once, from the later stamp. Never on the screen graph (docs/design.md 43). |
| Decision | Kind. One policy decision of a Run: a PolicyDecision node of the same layer under its own id, `agent:run/<stamp>/step-<n>/<pre\|post>`, with `layer`, `effect`, `phase`, `rule`, `step` and `reason`. Joined from its Run by `has-decision`; served by `GET .../agents/<name>/runs` only. Its page link is the layer page with the id after `#`, which marks its row (docs/design.md 43). |
| Emitter | What produced a mounted layer, named by the module its ontology names (`Graph.Emitter.Agent`). An emitter is a card of type `emitter` in one of the tenant's feeds, served as that Card under the card's own id; the card `Emitter.<X>` is the emitter `Graph.Emitter.<X>`. One a mounted layer names with no card in any feed is still served, as Kind Emitter flagged `unknown` and drawn in amber. Served by `GET /api/tenants/<tenant>/emitters`; listed at `/<tenant>/emitters` (Emitters/Catalogue), each at `/<tenant>/emitters/<name>`, while the Emitters service's other pages keep their paths there. A ledger line pushing an emitter card named like one of those pages stops the boot (docs/design.md 44). |
| Bootstrap | `New-PortalToken -Name <name> -Bootstrap`: makes a tenant's first principal, an admin with `createdBy` null, and its token. Once: with any principal already in `principals.yaml` it is an error, and a file with a second null `createdBy` stops the binary (docs/design.md 38). dev-bootstrap does not count: the real first admin is made beside it. |
| dev-bootstrap | The admin `Invoke-Build Dev` mints in a tenant of mode dev, `ui:principal:dev-bootstrap`, `createdBy` null wherever it sits in `principals.yaml`. Its tokens work only in mode dev (401 otherwise); `GET .../dev-token` hands one to the page's "Use dev token", only to 127.0.0.1. The name is reserved: no Add and no `New-PortalToken -Name` makes it (docs/design.md 39). |
| Role | What a principal may do: `reader` (GET only), `contributor` (every write but identity and settings) or `admin` (all). Identity is creating principals and revoking tokens. A write the role does not allow is 403; a write with no token stays 401 (docs/design.md 38). |
| Attenuation | A principal creates principals of a role equal to or below its own, never above. Enforced by the server before the admin check (a contributor asking for an admin is refused for attenuation) and at boot over `principals.yaml` (docs/design.md 38). |
| Token | A bearer token, stored only as its SHA-256 in `tenants/<tenant>/tokens.yaml` (gitignored), with the `principal` it belongs to and when it was `created`. `New-PortalToken -Name <principal>` issues one; a principal may hold several. Listed by owner and the first 12 hex digits of the hash (`GET .../tokens`); an admin's Revoke removes it (`DELETE .../tokens/<id>`). A token the tenant does not hold is refused (401). |
| Legacy token | A `tokens.yaml` entry from before 0.5.0, with `name` and no `principal`: it acts as an admin named after the token until it is revoked, cannot create principals (it has no id to record as `createdBy`), and the binary names it in a warning at boot (docs/design.md 38). |
| Identity files | `principals.yaml` and `tokens.yaml`: with the ledger, the only files the binary writes outside `-artifacts`, each replaced whole and atomically on an admin's Add or Revoke, after re-reading both, so a token minted since boot goes live with the write (docs/design.md 38). |
| Read-only | What the page does for a principal that may not write (`writes` false: `anonymous`, or a `reader`, whose tooltip names its role instead). Every control that would write (collapse, expand, Approve, the Designer's adds and section toggles) is disabled with the tooltip `sign in to write`. A write the portal still refuses (401) is a toast; the panel keeps drawing what the graph holds and never shows the error body (docs/design.md 37). |
| Marker | The holder the banner names, or `none`. Nothing issues markers yet; whoami's `marker` is always null (docs/design.md 36). |
| Service connection | An entry of `tenants/<tenant>/connections.yaml` (gitignored): `name`, `type` (`github`), `url`, `token_env`, the environment variable holding its secret, and `created_by`, the id of the principal who made it (served as `createdBy`; null in a file from before 0.5.0). The API lists connections without secrets. A github connection's repositories come back as `git.repository` nodes, id `ui:conn:<connection>/<owner>/<repo>`, to a caller with a token only: the call spends the tenant's secret. |
| Feed | Kind. Where cards are published: one entry of the merged config's `feeds:` (`portal.base.yaml`'s `cards-oci` and `cards-nuget`, a tenant's overlay overriding by `id` or adding), `ui:feed:<id>` with `kind` (`oci`, an OCI registry, or `nuget`, a NuGet v3 feed), `url` (the registry and repository namespace, or the service index), `visibility` (`private` or `public`; recorded, not enforced), and `tokenEnv`, the variable holding its API key. Served with its cards by `GET .../feeds`; never on the screen graph (docs/design.md 40). |
| Card | A Graph.Node manifest card: a folder holding `manifest.yaml` (Graph.Node design 21) and the files it needs. Pushed with `POST .../feeds/<feed>/push` (`Publish-PortalCard`) by a contributor or admin, checked with Graph.Node's manifest schema, and sent on as an OCI artifact or a `.nupkg`. Also the Kind of a card a feed holds, `ui:card:<feed>/<name>@<version>` (`feed`, `version`, `type`, `hash`, `digest`, `pushed`, `pushedBy`), joined from its Feed by `has-card` and derived from the ledger (docs/design.md 40). A Card of type `emitter` is an emitter: `GET .../emitters` serves it with `emitter` and `layers`, joined to its layers by `has-layer` (docs/design.md 44). |
| Content hash | A card's `sha256:<hex>` over one line per file, sorted by path: the path, a tab, the file's SHA-256, a newline. The same whatever feed holds it; the feed's own name for what it stored is the `digest` (the OCI manifest digest, or the `.nupkg`'s SHA-256) (docs/design.md 40). |
| Ledger | `tenants/<tenant>/ledger.jsonl` (gitignored): one JSON line per push that names a feed the tenant has, appended and never rewritten: `at`, `principal` (null for a legacy token), `name`, `role`, `feed`, `kind`, `card`, `version`, `type`, `hash`, `digest`, `files`, `result` (`pushed`, `duplicate`, `invalid`, `failed`), `message`, and since 0.10.0 `seq` (its line number) and `prev` (the SHA-256 of the line before; 64 zeros for the first), which chain it. Read and checked at boot; a broken chain does not stop the boot. With the identity files, the only files the binary writes outside `-artifacts` (docs/design.md 40, 45). |
| Ledger chain | A ledger whose every entry names the hash of the one before. Two are served by `GET /api/tenants/<tenant>/ledger` as Kind Ledger: `ui:ledger:agent`, the agent's ledger read from the mounted layer holding LedgerEntry nodes under `ledger:<seq>` ids, and `ui:ledger:portal`, the tenant's own push ledger. Listed at `/<tenant>/ledger` (Ledger/Entries), each chain's entries at `/<tenant>/ledger/<source>`, one entry at `/<tenant>/ledger/<source>/<seq>`; Ledger/Verify and Keys keep their paths, and a ledger page with the id `agent` or `portal` stops the boot (docs/design.md 45). |
| Verify | Whether a chain holds: each entry's seq is one more than the one before and its `prev` is that entry's `hash` (64 zeros before seq 1). `valid` true is drawn green; false is red with `breakAt`, the seq of the first entry that does not follow, and `reason` (`prev-mismatch`, `seq-gap`, `unchained`, or `layer` when the agent layer's own root says broken). Lines from before 0.10.0 at the head of Portal's ledger are `unchained` and never a break (docs/design.md 45). |
| LedgerEntry | Kind. One entry of a chain: `ledger:<seq>` for the agent's (Claude.Agent.Alerts' prefix, the id its layer gave it), `ui:ledger:portal/<seq>` for Portal's. Joined from its Ledger by `has-entry`, to the entry before by `prev`, and an agent entry to its Run or Step by `records`, which ends in the runs layer; its run's link is `/<tenant>/layers/<runLayer>#<id>` (docs/design.md 45). |
| Environments graph | Every node of an `environment.*` Kind in the mounted layers (`environment.instance` today), with its layer's id, Kind and properties, and the node one edge away: a Run or a Principal as Portal serves them, joined by `has-run` when the principal holds the run, else the node as its layer emits it. It is not a Kind, and Portal adds none: the layer's edges (`member-of`, `runs-as`, `hosts`) keep their kinds. The nodes carry `env`, `group` and `tags` when their layer gives them; Portal reads them and infers none, so a node without `env` is `unset`. Served by `GET /api/tenants/<tenant>/environments/graph`; drawn at `/<tenant>/environments/graph` (Environments/Graph), the selected node after `#`. An Environments page with the id `graph` and another view stops the boot (docs/design.md 46). |
| Node menu | What right-click or Shift+F10 opens on a node of the environments graph or a row of an `environment.*` page: Details (the node's item page), Show graph, Runs (the run a `hosts` edge reaches) and Ledger (that run's entries). Each item is a link, greyed when no edge leads to it (docs/design.md 46). |
| Screen graph | The envelope `GET /api/tenants/<tenant>/screen` returns: module `Portal`, `root` `ui:root`, every panel a node. Held in memory; it reaches disk only as a snap. |
| Boot | What a start loads the screen from: the snap `PORTAL_SNAP` names, else the newest snap, else the dev seed (`empty` with `-no-seed`). Reported in the `X-Portal-Boot` header (docs/design.md 20). |
| Container | Kind. A box holding Containers and Widgets by `contains`; arranged by its Layout, drawn with its Theme. Properties `parent`, `order`, `visible`, `bounds`. The root is the Container no `contains` points at. |
| Menu entry | A Container that `is-a` the Category named Menu and `opens` the Container or Widget it shows, contained by nothing. Until 0.4.0 the top bar drew these; the shell's rail is the tenant's menu now, and screen menu entries are listed and added by the Designer only (docs/design.md 36). The seed's are `ui:menu:graph`, "Graph", opening `ui:canvas` (docs/design.md 25), and `ui:menu:runs`, "Runs", opening `ui:canvas:agent-runs`, a Canvas on the `agent-runs` layer Claude.Agent mounts (docs/design.md 35). |
| Widget | Kind. A panel; its Category (`is-a`) decides how it draws, `source` says what. Properties `type`, `source`, `bounds`, `order`, `visible`. |
| Layout | Kind. `mode` grid, flow or canvas; `columns` for grid (12 when absent). Joined by `laid-out-by`. |
| Category | Graph.Node base Kind used as a panel type. `name`, `properties.label` (required by Graph.Node), `description`. The base Categories Canvas, Table, Detail and Designer have renderers; any other draws with the base it `is-a`. The seeded Category Menu has no renderer: its Containers are menu entries. |
| State | Kind. Per-node display state: `collapsed`, `selected`, `scroll`, and `icon` for a Service or Page. Id `ui:state:<id without ui:>`, joined by `has-state`. A display Kind. |
| Designer section | One collapsible block of the Designer: Approve, Kinds (ontology.yaml), Categories, Add Panel, Add Container, Add Category, Add Menu Entry. Whether it is collapsed is a State node `ui:state:<Designer id without ui:>:<slug>` (`ui:state:designer:add-panel` for the seed's), joined from the Designer by `has-state`; seeded with Approve and Categories open, and added with those defaults to a booted snap that lacks them (docs/design.md 28). |
| Theme | Kind. How a Container and what it holds look: `color` (accent, `#rrggbb`), `opacity` (glass surface, 0 to 1), `font` (CSS font-family). Joined by `themed-by`; a Container without one takes its parent's. A display Kind, and a node like any other, so a theme change is a changed node in a diff (docs/design.md 22). |
| Display Kind | State or Theme: the only Kinds whose `properties` may hold display keys (docs/design.md 5). |
| Ref | Kind. A stand-in on screen for one node of a mounted layer (`layer`, `node`), so `displays` stays inside the envelope (docs/design.md 9). |
| Data layer | A Graph.Node envelope mounted read-only under a name (`POST /api/tenants/<tenant>/layers`); never written (docs/design.md 2). Each mounted layer has a page, `/<tenant>/layers/<name>`, the mount's `Location`: its counts, stamp and nodes, linked from Graph/Layers (docs/design.md 42), and a produced-by line linking its emitter (docs/design.md 44). In `GET .../emitters` it is Kind Layer, `ui:layer:<name>` (`emitter`, `module`, `version`, `stamp`, `nodes`, `edges`, `mountedBy`, `path`), joined to its emitter by `produced-by`. A page that draws a screen node shows its layer in the toolbar: name, node and edge counts and stamp (docs/design.md 33, 36). |
| Mount | Kind. A layer mounted by path through `POST /api/tenants/<tenant>/layers`, recorded on screen as `ui:mount:<layer>` (`layer`, `path` as given, made absolute, and `mountedBy`, the principal whose token mounted it), so an approved snap mounts it again at boot, under the same principal (docs/design.md 43). A mount by envelope removes it; flag mounts are never recorded. No edges; it draws nothing (docs/design.md 33). |
| Source | A Widget's `source`: a layer name and optional `?kind=&from=` query. |
| Bounds | `{x, y, w, h}`: grid cells under grid, pixels under canvas. |
| Snap | The screen graph written to `artifacts/snaps/<stamp>.graph.json`; `<stamp>` is UTC with milliseconds, `:` as `-`. The newest is what the next start boots from. |
| Approve | `POST /api/snap` with an optional `note`, the Designer's Approve button: writes a snap whose envelope carries the note as an `approved` finding, and answers with the ids added, removed and changed against the snap before it (docs/design.md 21). |
| Diff | `GET /api/diff`: snap b against snap a, `added`, `removed`, `changed`, and `merged`, the Graph.Node design 11 merge with `absent` findings. |
| Production mode | `PORTAL_MODE=production`: nodes that `is-a` Designer are left out of the screen (docs/design.md 3). |

## Kinds

| Kind | Properties (required in bold) | Edges |
|---|---|---|
| Container | `parent`, `bounds`, `order`, `visible` | `contains` → Container, Widget; `laid-out-by` → Layout; `themed-by` → Theme; `is-a` → Category; `opens` → Container, Widget; `has-state` → State |
| Widget | `type`, `source`, `bounds`, `order`, `visible` | `is-a` → Category; `displays` → Ref; `has-state` → State |
| Layout | **`mode`**, `columns` | `has-state` → State |
| Category | **`label`**, `description` | `is-a` → Category; `has-state` → State |
| State | `collapsed`, `selected`, `scroll`, `icon` | (target of `has-state`) |
| Theme | `color`, `opacity`, `font` | (target of `themed-by`) |
| Ref | **`layer`**, **`node`** | `has-state` → State |
| Mount | **`layer`**, **`path`**, `mountedBy` | (none) |
| Service | **`path`**, `order`, `dock` | `has-page` → Page; `has-state` → State |
| Page | **`path`**, `order`, `nodeKind`, `view`, `screen`, `sections`, `filter` | `has-page` → Page; `has-state` → State |
| Principal | **`type`**, **`role`**, `created`, `createdBy` | `has-run` → Run |
| Feed | **`kind`**, **`url`**, **`visibility`**, `order`, `tokenEnv` | `has-card` → Card |
| Card | **`feed`**, **`version`**, **`type`**, **`hash`**, `digest`, **`pushed`**, **`pushedBy`**, `emitter`, `layers` | `has-layer` → Layer |
| Emitter | **`unknown`**, **`layers`** | `has-layer` → Layer |
| Layer | **`emitter`**, **`module`**, `version`, **`stamp`**, **`nodes`**, **`edges`**, `mountedBy`, `path` | `produced-by` → Card, Emitter |
| Run | **`layer`**, **`startedAt`**, **`stopped`**, `finishedAt`, `exit`, **`steps`**, **`allow`**, **`deny`**, **`witness`**, `ledger` | `has-decision` → Decision; `recorded-in` → LedgerEntry |
| Decision | **`layer`**, **`effect`**, **`phase`**, **`rule`**, **`step`**, `reason` | (target of `has-decision`) |
| Ledger | **`source`**, **`count`**, **`valid`**, `first`, `last`, `breakAt`, `reason`, `stamp`, `layer`, `claimed`, `unchained`, `entries`, `run`, `next` | `has-entry` → LedgerEntry |
| LedgerEntry | **`source`**, **`seq`**, **`stamp`**, **`hash`**, `prev`, `unchained`, `written`, `event`, `run`, `runLayer`, `by`, `feed`, `card`, `version`, `result`, `message` | `prev` → LedgerEntry; `records` → Run, Step |

Finding Kinds: `absent` (info), set by the diff on an element in snap a and not in snap b; `approved` (info), set by Approve on the snap envelope, its message the note.

## Problem codes

Graph.Node's: `schema`, `duplicate-node`, `duplicate-edge`, `dangling-edge`, `edge-id`, `edgeid`, `counts`, `kind`, `stamp`, and for ontologies `display` and `action`. Each carries a `severity`, `error` or `warning`; only errors refuse, and a dangling edge on screen is always an error here (docs/design.md 19). The portal's, all errors:

| Code | Means |
|---|---|
| `id-prefix` | A screen node id does not start `ui:`; or, in an envelope the API serves, a Run or Decision id that is not a valid `agent:` id, or a LedgerEntry id that is neither `ui:` nor a valid `ledger:` id. On the screen each is `ui:` like any node. |
| `unknown-kind` | The Kind is not in `ontology.yaml`. |
| `unknown-property` | A property the Kind does not declare. |
| `property-type` | A property of the wrong type, a required one missing, `mode` not grid/flow/canvas, `bounds` or `scroll` malformed, a Theme `color` not `#rrggbb`, `opacity` outside 0 to 1, a blank `font`, a Mount whose `layer` is not a layer name or whose id is not `ui:mount:<layer>`. Also a Category with no `properties` at all, which Graph.Node 0.2.0 lets through (docs/design.md 10). |
| `display` | A display property (`display`, `color`, `shape`, `icon`, `collapsed`, `selected`, `scroll`, `opacity`, `font`) on a node that is not a display Kind, or on an edge. |
| `unknown-edge-kind` | The edge Kind is not in `ontology.yaml`. |
| `edge-endpoints` | The edge's ends are not of the Kinds its edge Kind allows (an `opens` to a Layout, say). |
| `unknown-category` | An `is-a` to something that is not a Category on screen, or a Widget `type` naming no Category. |
| `unknown-ref` | A Ref names a layer that is not mounted or a node it does not hold. |
| `unknown-field` | A top-level node key other than id, kind, name, properties, source, findings, stamp. |
| `file` | In a refused push (422): a card file's path that is empty, absolute, not clean, holds `..` or a backslash, repeats another's without case, is `manifest.yaml` (which is the manifest part), or names what a `.nupkg` reserves at its root (a `.nuspec`, `[Content_Types].xml`, `_rels`, `package`). The manifest's own problems are Graph.Node's `schema`, at paths `manifest.yaml:/...` (docs/design.md 40). |
| `ontology` | In a layer's `ontologyProblems`: its ontology is a URL, relative to an inline envelope, or unreadable; the layer draws grey (docs/design.md 14). |

## Not here yet

- Edges across envelopes, which would retire Ref (docs/design.md 9).
- Real data on the shell's pages beyond Graph/Explore, the Designer pages, Designer/Themes, Identity/Users, Settings/Tokens and Settings/Service connections; markers; connection types beyond github; OAuth or sessions (docs/design.md 36).
- Agents as principals (minted via Marker), issuing a token from the page, changing a principal's role or removing one, and settings writes (docs/design.md 38).
- Emitters/Sources, Runs and Schemas still list Kinds nothing emits; a layer whose module is named like one of those pages has its emitter page shadowed by the page (docs/design.md 44).
- Pushing from the page, enforcing a feed's `visibility`, deleting or unlisting a card, and using Postgres (docs/design.md 40).
- Ledger/Verify and Keys still list Kinds nothing emits; a MAC check of either chain (it needs a key Portal does not hold); serving `recorded-in`; and Graph.Node's registry naming who besides Claude.Agent.Alerts may issue `ledger:` ids (docs/design.md 45).
- Environments/Images and Networks wait for a layer emitting `environment.image` and `environment.network`; kubernetes and host instances are coloured but none is emitted; dragging or releasing a pin by keyboard; a ledger node in the environments graph, which needs an edge from an environment to it (docs/design.md 46).
- An edge deletion route (docs/design.md 15).
- A drift check for `internal/gen` (docs/design.md 16).
- Editing a Theme from the Designer (docs/design.md 22).
- Graph.Node refusing a Category with no properties, a Graph.Node 0.2.1 item (docs/design.md 10).
