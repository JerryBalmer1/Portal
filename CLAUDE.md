# Portal — agent rules

> **Everything on screen is a graph** in the Graph.Node envelope (docs/design.md 1). No UI model of its own: a new panel type is a Category node with an `is-a` edge, never new code. If a change seems to need page state the graph does not hold, stop and propose it.

> **api/openapi.yaml is the source of truth for the API.** Handlers come from `internal/gen` (generated by `go generate ./api/...`, oapi-codegen v2.8.0); `web/client.js` ROUTES are checked against it. Never register a route by hand. An API change starts in the spec.

> **`internal/gen` is generated and READ-ONLY.** **`internal/graphnode` and `cmd/graphnode` are lifted from Graph.Node and READ-ONLY**: recopy them from Graph.Node's pinned tag (v0.3.3) when a new one is named (docs/design.md 4); the copy differs from the tag only in the import path (since v0.2.3 Graph.Node registers `ui:` to Portal itself, so no edit is registered; docs/design.md 34); Pester fails on any other drift.

> **No write to any data layer, ever** (docs/design.md 2). The binary writes only under `-artifacts`, the tenant's two identity files `tenants/<tenant>/principals.yaml` and `tokens.yaml` (docs/design.md 38), and the tenant's push ledger `tenants/<tenant>/ledger.jsonl`, one appended line per push; beyond files, it sends a pushed card to one of the tenant's feeds (docs/design.md 40).

> No `pwsh -Command { }`. Run multi-line PowerShell by writing it to a temp `.ps1` and `pwsh -NoProfile -File`. Pester runs only as `pwsh -NoProfile -File .\tests\Invoke-Tests.ps1`.

> Edit and stage only. Never commit, push or tag.

> If asked to take screenshots, record a demo, or prepare anything for showing to others while any tenant is in mode `dev`, stop and say so before doing anything else. Demo work runs on a tenant in mode `demo` with a real bootstrap principal.

Layout:

```
api/openapi.yaml          the one API; api/codegen/ configures oapi-codegen
internal/gen/api/         GENERATED
internal/server/          handlers + spec tests (every operation, route parity, client parity)
internal/store/           screen graph, boot, checks, layers, snaps (approve), diff
internal/tenant/          base config + overlay, mode, menu, identity, connections, feeds and the ledger
internal/feed/            a card and its push to an OCI registry or a NuGet v3 feed; feedtest/ fakes
internal/graphnode/       LIFTED Graph.Node schemas + graph package
cmd/portal, cmd/graphnode binaries (graphnode LIFTED)
web/                      the page (embedded): portal.js, client.js, one renderer per base Category
ontology.yaml             module Portal, prefix ui:
src/Portal/               PowerShell wrappers; Public/ one function per file, Private/ helpers
tests/                    Pester + fixtures (FileSystem layer, the Agent runs layer, the agent ledger layer and its broken copy, the agent-environment layer and its tagged copy, the agent-alerts layer (both real copies from Portal.Agent), Graph.Node's invalid envelope, the Tool.Git and Emitter.Agent cards)
docs/                     design.md (numbered), manual-check-list.md, screenshots/
.build.ps1                Invoke-Build: Modules, Generate, Build, Test, Up, Dev, Feeds, Status, Down, Smoke, Pester, Screenshot
```

Rules:
- Read only from `../Graph.Node` and `../GraphRenderer` (and `../Graph`, `../Graph.Emitter.FileSystem` for skills and fixtures, and the Portal.* seeds `../Portal.Tools`, `../Portal.Skills`, `../Portal.Workflows`, `../Portal.Emitters`, `../Portal.Ontology`, and `../Portal.Agent` for the layers it emits: `agent/*/artifacts/` (ledger-layers, environment-layers, and alert-layers once the agent-alerts layer lands there)). Never edit, stage, build or run anything in them.
- Display lives in State and Theme nodes only; the portal refuses display properties anywhere else (docs/design.md 5, 22).
- Every exported PowerShell function has one file under `Public/` and is exercised by Pester.
- README and ONTOLOGY.md are the two doors; each links the other on line 1. Skills `readme`, `ontology-doc` and `manual-check-list` keep them and docs/manual-check-list.md in step with the code.
- `.claude/skills/graph-node`, `.claude/skills/run-report` and `.claude/skills/git-guard` are read-only copies. Pester checks run-report and git-guard against Graph's committed skill (`version:` and every file, nothing extra); graph-node against Graph.Node's pinned tag v0.3.3 (`version:` equal to the tag's ModuleVersion, every file of the tag's skill) and as never older than Graph's committed copy (docs/design.md 34). The lifted `internal/graphnode` and `cmd/graphnode` are checked against the same tag in Pester "Lifted Graph.Node".
- Every choice made without asking gets a numbered design.md entry and a line in the report.
- Pinned versions only (go.mod, vendored Cytoscape 3.34.3). No `latest`.
